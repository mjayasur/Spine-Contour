# Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the vanilla-ES-module renderer architecture — tokens, fonts, the `SS` backend rename, Landing, Sidebar, and a stub Studies screen — so the app launches, gates on the research-use acknowledgement, and lets a user navigate between screens with working theme and collapse controls.

**Architecture:** A single `renderer/store.js` holds all app state behind `getState`/`setState`/`subscribe`; `renderer/router.js` reads `state.screen` and mounts the matching screen module (plus the persistent `Sidebar`) into `#app` using the tiny `renderer/dom.js` helper. `renderer/api.js` is the only module allowed to call `window.spineContour`, normalising IPC errors into display-ready messages. Every screen and component is a plain function `render(state) → HTMLElement`; there is no virtual DOM and no two-way binding — a state change triggers `router.js` to rebuild the affected subtree from scratch.

**Tech Stack:** Vanilla ES modules (no bundler), Electron 44 main/preload/renderer processes, plain CSS with custom properties, Node's built-in `node --test` runner, Python/FastAPI backend (pytest).

## Global Constraints

- No bundler, no framework, no npm runtime dependencies. Vanilla ES modules only. `package.json` `dependencies` stays empty; `devDependencies` stays exactly `electron` and `electron-builder`.
- CSP is `default-src 'self'; img-src 'self' blob: data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'none'`. It must not be loosened. No CDN, no Google Fonts, no remote anything.
- Fonts are self-hosted from `assets/fonts/`. Source Sans 3 and Chivo Mono, both SIL OFL.
- Never display a fabricated measurement. Absent values render the em dash `—`, never `0`, never `N/A`, never a guess.
- Never label a value with a name it isn't. See the `SS` rename (plan 02) and the `FEMORAL FIT CONFIDENCE` badge (plan 03).
- Node's built-in test runner only (`node --test`). No Jest, Vitest, or Mocha.
- Every `<script>` is `type="module"`. No global scope leakage.
- Target Electron 44 / Chromium — modern syntax is fine. No transpilation.
- Commit after every task. Conventional commit prefixes (`feat:`, `fix:`, `test:`, `chore:`).

## Plan-specific notes (read before starting)

**`node --test <directory>` does not work in this environment.** Verified empirically on this machine (Windows, Node v24.19.0): `node --test test/` and `node --test test` both fail with `Error: Cannot find module '...\test'` — Node treats the bare directory as a CommonJS entry-point argument instead of a search root. `node --test` with **no** path argument (auto-discovery from `cwd`) works, and an explicit glob `node --test test/*.test.js` also works and was confirmed to run multiple files correctly, including via `npm test`. Task 20 therefore adds `"test": "node --test test/*.test.js"` to `package.json`, **not** the `node --test test/` form. If a future Node version fixes directory arguments, this can be revisited — do not "fix" it back without re-verifying, the current form is the one known to work here.

**ESM under `node --test` needs a module-type boundary.** The repo's root `package.json` has no `"type"` field (defaults to CommonJS), which `main.js`/`preload.js` need, since they use `require()`. But `renderer/*.js` and `test/*.js` use `import`/`export`. Node resolves module type from the *nearest* `package.json`, so this plan adds two one-line marker files — `renderer/package.json` and `test/package.json`, each containing `{"type":"module"}` — so everything under those two trees parses as ESM while the project root stays CommonJS. This has zero effect on how Electron's renderer (Chromium) loads `renderer/main.js`, since `<script type="module">` in the browser ignores `package.json` entirely; the marker files exist purely for Node-side tooling (`node --test`, `node --check`).

**DOM-only modules use `node --check` for syntax verification, not a fake behavioural test.** Modules like `dom.js`, `router.js`, and every screen/component cannot be exercised with `node --test` because Node has no DOM and this project may not add `jsdom` (not an allowed dependency). Their "Step 4" is `node --check <file>`, which parses the file and confirms it is valid, loadable ESM — nothing more. Actual behaviour (clicks, rendering, navigation) is verified by launching the real app; that full walkthrough is Task 20, once every piece is wired together. Earlier tasks note where their specific behaviour will be exercised.

```js
export function el(tag, props, ...children) {
  const node = document.createElement(tag);
  if (props) {
    for (const [key, value] of Object.entries(props)) {
      if (value === undefined) continue;
      if (key.startsWith('on') && typeof value === 'function') {
        node.addEventListener(key.slice(2).toLowerCase(), value);
      } else if (key === 'class') {
        node.setAttribute('class', value);
      } else if (key in node) {
        node[key] = value;
      } else {
        node.setAttribute(key, value);
      }
    }
  }
  const flatChildren = children.flat(Infinity);
  for (const child of flatChildren) {
    if (child === null || child === undefined || child === false) continue;
    node.append(child instanceof Node ? child : document.createTextNode(String(child)));
  }
  return node;
}

export function clear(node) {
  while (node.firstChild) node.removeChild(node.firstChild);
}

export function mount(node, child) {
  clear(node);
  node.append(child);
}
```

```js
function cleanMessage(error) {
  const raw = error && error.message ? error.message : String(error);
  const marker = raw.lastIndexOf('Error: ');
  return marker >= 0 ? raw.slice(marker + 'Error: '.length).trim() : raw.trim();
}

async function invoke(channel, payload) {
  try {
    return await window.spineContour[channel](payload);
  } catch (error) {
    throw new Error(cleanMessage(error));
  }
}

export async function selectFile() {
  return invoke('selectFile');
}

export async function predict(request) {
  return invoke('predict', request);
}

  return invoke('measure', geometry);
```

```js
const SCREENS = {
  workspace: renderWorkspace,
  studies: renderStudies,
  analysis: renderAnalysis,
};

export function renderRoute(root, state) {
  if (!state.ack || state.screen === 'landing') {
    mount(root, renderLanding(state));

  const page = el('div', { class: 'app-page' }, shell, renderToast(state));
  mount(root, page);
}
```
